What it scans

Six strategies, one ranked list of opportunities

Each scan reports cost, expected revenue, profit and ROI, ranked best first. Every result expands to show each possible output skin, its drop probability, and whether that outcome wins or loses.

trade-ups

For every collection, simulates buying 10 of the cheapest skin at a rarity and trading up to the next tier.

anomalies

Flags listings where the lowest ask sits far below the median — the classic "someone underpriced this" flip signal — filtered by trade volume.

covert → knife

Scans the Oct-2025 rule: five Covert skins from one weapon case trading up into a knife or gloves from that case's pool.

float-mix

Finds the cheapest mix of input wear conditions that steers the output into its most valuable wear bracket instead of leaving it to chance.

filler collection

Tests diluting a collection's inputs with a cheap skin from a second collection, using the group-based odds rules, to see if it beats going solo.

price verification

Cross-checks the cheapest input's Steam price against Skinport and CSFloat to catch a "drought" — Steam priced high on thin supply, not real value.

How the math works

Wear is a number between 0 and 1, so value is a bracket you can aim at

A trade-up's output wear is the average of its ten inputs' wear, rescaled into the output skin's own range. Because the same skin is worth far more Factory New than Battle-Scarred, deliberately mixing input conditions moves the output across a price boundary — that's the float-mix strategy.

Output skins are drawn from the combined next-rarity pools of the input collections, each weighted by how many inputs came from that collection. The scanner enumerates the full pool, prices every outcome, and sums probability × profit into one expected value.

ML calibrates; it never overrules. Once enough real trade-up outcomes are logged, a lightweight model predicts realised ROI and acts as a tiebreaker alongside the formula — surfaced everywhere, trusted nowhere as a replacement for the arithmetic.

Architecture

One engine, three ways to reach it

A pure-Python core does the pricing and simulation. A local HTTP server exposes it as an API. A React dashboard and a browser extension consume that API; a watch loop retrains the model in the background whenever enough new outcomes land.

Built inside the rules

It stops at "here are the opportunities"

Steam's Subscriber Agreement prohibits bots that buy or sell on the Community Market, so the tool deliberately does none of that. You review each opportunity and execute it yourself. Automated execution is a later phase, and only through marketplaces that publish an official trading API for it.

no login

Never authenticates to Steam. No account, no session, no credentials.

no orders

Places no buy or sell orders anywhere. Reads public price data only.

no inventory

Doesn't touch any inventory or balance. Nothing auto-buys.
