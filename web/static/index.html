How this works & what the numbers mean

1. The trade-up contract

A trade-up contract consumes 10 skins of the same rarity and the same collection, and returns 1 random skin of the next rarity tier up, drawn uniformly from that collection's pool at that tier. If a collection has n possible outputs at the target rarity, each one has a 1/n chance. Steam takes a cut when you resell the output -- currently modeled here as …% (STEAM_SELL_FEE in tradeup.py). Worked example: 10 inputs costing $1.00 each = $10 cost; if the expected resale value is $12, after the fee that's $12 × (1 − fee) ≈ $10.44, for roughly a 4% ROI.

When multiple collections are mixed into one contract (see "filler" strategies below), the Oct-2025 rules make odds group-based: a group's share of the 10 inputs is its total chance, split evenly across its own outputs (oddsmath.group_odds()).

2. Float manipulation

The output's float (wear condition) is the average of the 10 input floats, each normalized into its own skin's min/max range, then re-applied to the output skin's own range. Buying a deliberate mix of wears -- instead of whatever's cheapest -- can steer the result into a more valuable wear bracket. 3. Third-party drought detection

Steam's own listing supply for a specific skin+wear can run temporarily thin, pushing its Steam price well above what the same item sells for elsewhere. This tool cross-checks against Skinport (and CSFloat, if configured) and flags a "drought" when Steam is priced …% or more above the cheapest verified alternative -- an annotation only, never a change to the cost/ROI numbers.

4. ML-assisted ROI calibration

Once you've logged …+ real trade-up outcomes (see "Learning from real trades" below), a HistGradientBoostingRegressor (scikit-learn) is trained on features like the wear-mix composition, whether a filler collection was used, StatTrak, cost, and the formula ROI at the time, to predict realized ROI. It's consulted only as a tiebreaker between near-identical formula-ROI candidates, never to override a clear formula winner. It retrains automatically once … new outcomes accumulate. Glossary

ROI
Return on investment: profit ÷ cost × 100, after the Steam fee.
Float
A number from 0.00 (cleanest) to 1.00 (most worn) determining a skin's exact wear within its bracket.
Wear
The five named condition brackets a float falls into -- see the chart above.
StatTrak
A variant that tracks kills; priced and traded separately from normal copies.
Collection vs. case
Regular trade-ups group skins by collection; the Covert->knife/glove trade-up groups by weapon case instead.
Drought
A temporary Steam-specific supply shortage that inflates Steam's price relative to other markets.

Multi-agent simulation (6 agents: 4 specialists + 2 meta)

Generates totally random, plausible trade-up candidates (random skins/collections/floats spanning multiple collections, respecting each skin's real float cap), simulates each one's expected ROI, and logs every trial to its own data/sons/son_N/simulations.jsonl. Four independent named agents run in parallel, each with a distinct search personality (8 behavioral parameters -- exploration, risk tolerance, collection-mixing bias, wear-optimization bias, liquidity importance, ROI weight, mutation strength, memory weight) and its own separately-trained search-heuristic ML model. Five of those parameters self-tune automatically: every few rounds an agent A/B-tests a small tweak of its own search preferences and keeps it only if it beat the previous window on an ROI-first reward that also pays a bonus for exploring under-tried collections (and penalizes unpriceable candidates) -- so preferences chase real ROI without ever giving up on new skins/collections; candidate selection additionally carries an uncertainty bonus for collections an agent has rarely simulated, so a powerful trade-up hiding in unexplored territory can't be starved out of the budget. The risk/liquidity admission gates and each agent's ROI trust weight stay fixed so an agent can never "improve" its reward by lowering its own quality bar. The radar chart below shows the LIVE (self-tuned) parameter values, drifting in real time. Because the four agents search independently, if one plateaus the others keep making progress, and a plateaued ("stuck") one can be individually Nudged (a temporary push back toward exploring, keeps its data/model) or Fully reset (wipes that one agent's data/model and starts it over). An anti-convergence watcher automatically nudges agents that settle on the same strategy for too long. This is a THEORETICAL, formula-based estimate from candidates nobody has bought or sold -- a search heuristic, not a market oracle -- and is kept entirely separate from the real ROI-calibration model above (trained only on outcomes you actually logged). See the Results page for its curated finds, the full archive, and leaderboards.

Evolution Manager (Evolution Engine 2.0)

Cross-agent cooperation layered on top of the population above -- the specialist agents themselves are never modified. Maintains a cross-agent Elite Population (fitness = the same composite score the final ranking uses, so fake high ROI can't capture it), injects other agents' elite finds into each agent's mutation pool (tournament parent selection with a novelty-biased slice), groups elites into species whose stagnation raises that species' mutation pressure, keeps an all-time Hall of Fame, refreshes the two Meta agents' inherited personalities by behavioral crossover from the best-performing specialists every 6h, and periodically copies a mutated version of the best agent's self-tuning hyperparameters onto the worst's (population-based training). Every admission, injection, meta refresh and hyperparameter transfer is logged to data/evolution/lineage.jsonl. Disable it any time -- every hook goes neutral and the population behaves exactly as before.

Exploration Recovery Mode

Extends the STUCK detection above: if an agent stays stuck well past the point where a nudge had its chance, it enters Recovery Mode -- progressively raising mutation, exploration, novelty weighting and search diversity while lowering exploitation bias (levels 1-4, pure multipliers on the live self-tuned params, instantly undone on exit). If it's STILL stuck at max escalation, each adaptive parameter gets an independent, bounds-clamped random perturbation (some up, some down). The mode exits the moment a real improvement lands. Automated GitHub backup (delta-aware, every 6h)

A background worker wakes every 6 hours, SHA-256-hashes the mutable telemetry files (outcomes.jsonl, price_history.jsonl, dead_skin_scores.json) and compares them against the last successful backup. Unchanged → logs "No telemetry mutations detected" and sleeps. Changed → wraps data/ into archive_YYYYMMDD_HHMMSS_[skins]skins_[outcomes]outcomes.zip via the same export-data pipeline as the button above, then commits + pushes it to the git repository configured below. Rare Pattern Opportunities (Collector Arbitrage -- independent from the trade-up optimizer)

Scans marketplace listings for items whose seller priced a documented collector pattern (Blue Gems, Case Hardened tiers, Heat Treated seeds, Doppler phases, rare fades, Katowice/Crown sticker crafts…) at ordinary market price. Detection is knowledge-driven, never ML-driven: a listing only ever becomes an opportunity by matching the versioned Pattern Knowledge Database below (public collector consensus, every entry links its source) -- no model can invent a pattern. Valuation cross-checks the base skin's consensus price across Steam/Skinport/Buff163; a base price fewer than 2 sources confirm has its confidence demoted automatically. CSFloat is the only marketplace whose public listings carry float + paint seed, and it requires a free API key (CSFLOAT_API_KEY) -- the scanner status below says so plainly if it can't scan. As always: read-only, nothing is ever bought -- verify float/seed on the listing itself before spending money.
